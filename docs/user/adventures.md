# 冒险与创建游戏

最新界面流程见[内容与游玩](../zh/content-and-play.md)（[English](../en/content-and-play.md)）。

## 从模组开始一局冒险

1. 先在 **内容包** 页面安装并预览兼容的内容包。
2. 在模组详情中点击目标冒险的 **用此冒险创建游戏**。
3. 创建页会预选该模组与冒险、兼容规则，以及固定或可用的推荐世界；也可以自行调整。
4. 检查冒险与当前规则、世界的兼容性。
5. 创建或选择角色，完成开团设置后开始游戏。

创建游戏时，DiceFrame 会把冒险的身份、版本和内容摘要绑定到这份存档。它还会通过既有世界与规则入口准备所需内容。游戏里的 NPC、地点、关系、任务进度和其他变化保存在游戏存档中；不会反向修改原始模组。

## 通用剧情与本局计划

新建、文字导入和剧情计划转换默认使用**通用剧情**包。同一个剧情包可用于支持
剧情图的 CoC、自定义规则和 D&D 对局；战斗、奖励和专属检定不会跨规则自动转换。
旧 D&D 包继续要求原运行时。内容库和创建页会检查规则与世界要求。

本局已采用的计划可在 **GM 工作台 → 场景 → 剧情计划 → 整理为冒险包** 中复制。
在审阅弹窗编辑、校验并确认发布后才进入冒险库。复制场景默认仅 GM 可见，包含
转场条件和提示；公开前须移走私密信息。不复制本局进度、人物状态或聊天记录。
详见[剧情计划指南](../zh/run-story-and-finale.md)。

## 冒险面板

绑定 v2 冒险后，游戏界面会显示冒险面板。

- GM 可以看到完整的图定义，例如章节、节点、目标、里程碑、场景引用和遭遇引用。
- 玩家与旁观者只会看到公开章节、公开节点和公开目标；隐藏内容及通向隐藏内容的跳转在服务端投影时就会被移除。
- 旧版 v1 冒险仍可正常作为绑定内容使用；面板会明确说明它尚没有 v2 图面板。

GM 可以完成当前开放的节点；服务端校验后保存进度，并开放满足条件的后续节点。推进与规则效果通过既有服务端边界执行，不从前端自行推断结果。

## 导入 Markdown 或 TXT 剧本

在 **冒险包管理** 页面打开 **导入剧本 / 外部模组**，上传 UTF-8 的 `.md` 或 `.txt` 文件（最多 512 KB）。先查看预览，修改章节、场景、入口和后续节点，再检查公开范围、重新校验并确认发布。发布后点击 **用此冒险创建游戏** 即可开团。

```markdown
# 雾港调查
## 第一章
### 抵达 {#arrival}
港口浓雾。
GM: 凶手藏在仓库。
@choice 调查仓库 -> warehouse
### 仓库 {#warehouse}
调查仓库，寻找线索。
```

- `#` 是标题，`##` 是章节，`###` 是场景；`{#arrival}` 指定场景 ID。
- 没有分支标记时，普通场景按文件顺序连接。新导入的 `@choice 描述 -> 场景ID` 使用排他选择，GM 确认一条路线；旧并行图保持原有同时开放语义。
- `GM:` 仅标记当前行，作为单独的 GM 私密备注保存。所有导入节点默认只给 GM 看，公开朗读内容需在预览中显式改为公开。
- `@npc guard`、`@location harbor`、`@encounter ambush` 声明资源引用。找不到的引用会阻止发布；第一版可以明确选择 **仅保留为文字资料**，重新校验后发布。
- 代码块和未知标记保留为文字。导入不会自动生成怪物数值、法术效果或规则计算，也不执行脚本。

预览和取消不发布内容。修改预览后必须重新校验；重复文件会提示身份冲突，可在身份设置中改用新的目录 ID 和冒险 ID。已被存档绑定的版本受现有只读保护约束，继续修改需要复制出新冒险。

## AI 整理导入草稿

导入文件并点击 **解析并预览** 后，可以使用 **AI 整理草稿**。此操作使用设置中配置的主模型，会把草稿正文发送给该模型服务，并消耗模型 token；较长资料会分段调用模型。开始前需要勾选用量提示旁的确认框。

1. 可填写整理要求，例如按章节组织场景、保留线索和 GM 秘密，然后点击 **开始 AI 整理**。
2. 进度条显示实际完成的分段整理、剧情连接和草稿校验步骤，不表示预计耗时。可以随时点击 **取消整理**；关闭导入弹窗也会中断请求。取消前已产生的 token 用量仍可能计费。
3. 完成后先查看 **结果预览**，确认场景和资源是否合理。点击 **采用 AI 草稿** 才会替换当前草稿，也可以丢弃结果。生成失败、取消或结果尚未采用时，AI 不会替换当前编辑内容。
4. 采用后继续人工审核，按需编辑、重新校验并勾选检查确认，再点击 **发布为冒险**。原文保留为 GM 参考节点，AI 生成的场景和资源也默认仅 GM 可见。

AI 可以整理剧情场景、NPC、物品和地点资料，建议场景间的连接。它不会自动把怪物数值、法术、奖励或房规变成可执行机制，也不会改变冒险身份、版本和规则运行时。单次整理最多支持 128000 个正文字符，超出时应分章节导入；未配置主模型时会明确报错。

## 原生排他选择

原生冒险支持排他选择：玩家可提出候选分支，GM 确认后提交一个结果。私密提议和完整候选资料按服务端权限投影；过期局次或状态版本会被拒绝。新文字 `@choice` 和本局计划的多条候选路线使用这一选择语义。

## 绑定为什么重要

同一存档必须继续使用相同的冒险版本与内容摘要。若安装的内容不同，DiceFrame 会停止展示可继续使用的内容，而不是让剧情、NPC 或遭遇在旧存档中悄悄变化。

这同样保护回滚与重开：它们应回到与存档一致的内容，而不是切换到后来安装的版本。

## 找不到或不兼容怎么办

游戏中的冒险面板会显示所需的冒险 ID 与版本，并提供“前往模组库”。在模组库中：

1. 导入或安装包含该冒险的正确版本模组。
2. 使用安装预览确认没有阻断项。
3. 返回游戏并刷新。

DiceFrame 不会自动降级、自动迁移或用近似版本替代。将来若有旧版本库或迁移流程，也必须是明确选择并经过检查的操作。

## 公开内容、手册与遭遇

玩家只应依据游戏中公开显示的目标、线索和手册行动。GM 私密信息、未公开遭遇或世界内部过程不应通过截图、链接或前端缓存共享给玩家；权限边界由服务器负责，而不是依赖客户端隐藏按钮。
