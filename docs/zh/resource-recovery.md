# 恢复与幕间资源

本页说明 DiceFrame 提供的轻量恢复与幕间功能。它是产品使用说明，不是完整的官方《克苏鲁的呼唤》规则复刻。

## 打开面板

进入游戏后，在角色栏打开 **恢复 / 休整**。如果当前没有声明
`resource_recovery`，入口会隐藏，功能保持关闭。如果已经声明但结构错误、版本不支持或属于未来版本，入口仍会显示，面板会报告服务端校验错误并 fail closed。系统不会根据旧自定义规则猜测策略，也不会替你改写旧规则。

## 申请休息或治疗

1. 玩家在面板中选择 **过夜休息** 或 **治疗** 并提交申请。
2. GM 审核申请并选择批准或拒绝。
3. 批准后，服务端按策略声明的时长推进游戏逻辑时钟，检查角色当前状态，并以原子操作结算结果。

时钟使用申请以来已经经过的 elapsed time：服务端只推进剩余差值（`duration - elapsed`），批准或重试不会每次额外推进整段时长。

角色必须在场、存活、清醒且不在战斗中。SAN 为 0 或已永久疯狂的角色不能通过普通恢复复活。具体时长、资源和治疗技能由当前策略决定，不要从剧情文字标签推断这些数值。

内置 MVP 策略保持为固定的小范围配置：

- `coc_light` 支持八小时过夜恢复并掷 `1d6` SAN；治疗使用策略声明的技能，成功时掷 `1d3`。
- `coc7e_style` 不因过夜休息恢复 SAN，治疗使用 30 天精神分析。它只是风格策略，不是完整的官方规则实现。

## 发放并领取剧情奖励

GM 可以选择角色、选择 SAN 或 Luck，填写固定奖励规格（`1d3`、`1d6`、`1d10`）或范围内的整数，并记录原因。服务端先授权并记录奖励，玩家再在面板中点击 **领取**。提交奖励不会重复应用；同一操作重试也不会重复结算。

## 在幕间后恢复 Luck

队伍真实完成一次幕间后，GM 才能为该幕间打开 Luck 恢复操作。服务端掷 `d100`，只有结果大于角色当前 Luck 才成功；成功后增加 `1d10` Luck。检定失败会消耗该幕间的机会，刷新页面或更换客户端都不能重试。

## 队伍休息动态

队伍成员可在队伍栏的 **休息动态** 查看当前存档提供的近期申请和结算状态。
CoC 的休息、治疗申请与结束状态，以及协同短休、长休的状态会向队伍展示；
SAN/Luck 数值、治疗原因、检定骰值和 GM 私有奖励仍按原权限查看，不进入队伍通知。

新动态默认显示一次不抢焦点的轻提示，五秒后消失，也可以随时关闭。
在提示中点击 **不再提醒**，或在 **休息动态** 里关闭 **显示休息提醒（仅自己）**，
即可静音。偏好按当前设备、对局和身份保存，不影响其他成员、申请审批或规则结算。
静音后仍可主动查看动态；首次进入、刷新或重新开启提醒不会补弹已有记录。
通知不会写进剧情对话，也不会挤占输入区。协同休息只展示现有休息会话，
这里不是一份独立、永久保留的休息账本。

## 规则与兼容性

恢复使用固定的 v1 策略配置，不是通用规则 DSL。服务端负责逻辑时钟、角色数值、确定性随机种子、结算凭证和一次性记录。启用恢复策略后，剧情文字或旧式正向 SAN/Luck 标签不能授权正向变化。

没有有效策略的旧存档和自定义规则保持原状，不能使用本功能。DiceFrame 不会推断缺失策略、静默转换旧语义或强行迁移。存档跨越恢复权威边界导入时，如果存在待处理恢复操作会直接拒绝，不会从历史记录重建。

通过 P2P 连接的访客可以读取恢复状态，并使用玩家申请/领取操作。GM 批准、拒绝、发放奖励、Luck 检定、时钟推进和结算仍由服务端授权。
