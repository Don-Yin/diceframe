# 角色对话模式

创建游戏时，在“叙事表现”中选择“角色对话”，开场与后续剧情就会按旁白、
NPC 台词分别显示。创建后也可以进入 GM 工作台 → 设置 → 叙事表现切换。
切换会保存到当前对局，从下一次生成或重生成生效；已有记录保持原样。

普通叙事仍然可选。旧存档默认使用普通叙事，不会自动猜测过去的台词属于谁。
角色对话也沿用当前规则、玩家行动与多人回合推进方式。

台词右侧的播放按钮占用独立位置，长句和手动换行不会把按钮推到末行或挤出气泡。

## 角色很多时的头像

- 已有 NPC 头像直接复用。
- 没有图片时显示人物缩写和固定颜色，不会自动生成图片或消耗生图额度。
- GM 工作台的“对话人物头像”可以搜索全部已出场人物，选择内置头像、上传图片，
  或复用已有图片。选“无头像”可以恢复缩写显示。
- 同名人物分别管理，头像由人物编号关联；蒙面人等未揭示身份不会自动显示真名头像。
- 修改对话头像会更新同一人物的历史气泡，刷新或重新读档后仍有效。

主要角色可以配专用图，临时路人保留缩写即可。只需为真正需要辨认的人物维护图片。

## 同一个人物出现了两条头像记录

模型应复用已出场人物的编号。临时人物后来登记成 NPC，并不表示出现了第二个人；
提示协议也明确要求继续沿用原说话人身份。同名的不同人物仍分别保留，不按名字自动合并。

若已有重复，在 GM 工作台的“对话人物头像”中查看首次出场轮次和人物编号末尾，
展开临时记录的“合并重复人物”，选择确认为同一人的目标并确认。
合并统一头像、公开人物编号及后续识别，原始台词与存档记录保留；目标的独立头像优先，
目标未设置时保留临时记录的头像。不同公开身份、未出场人物和回合生成中的合并会被拒绝。
这些关联属于当前 run，新开一局不会继承临时人物的关联。

## 重生成和后续 Galgame 模式

每个重生成分支分别保存人物台词与旁白，切换分支时同步切换。聊天、Bot 文本、
历史记录继续使用同一份剧情。

底层保存的是带版本的有序剧情片段。后续 Galgame 的立绘舞台、发言者高亮和逐句
播放可以读取这些片段；当前功能提供聊天气泡展示与人物头像管理，尚未提供立绘
舞台、表情切换、人物独立配音或恋爱路线系统。
